# Free Demo Deployment (Render + Neon)

Status: demo only
Cost: $0 (Render free web service + Neon free Postgres)
Owner: whoever holds the Render and Neon accounts

## What this deploys

One Docker container runs:

- the Fastify API,
- the built React PWA, served from the same origin,
- migrations on boot,
- a one-time synthetic seed when the database has no users.

Serving the PWA and API from one origin is deliberate: the refresh cookie is
`httpOnly`, `SameSite=Lax`, so a split frontend/API origin would break session
refresh. It is a demo deviation from ADR-006 (nginx edge + separate API
containers); do not use it for PHI.

> **Data warning:** this stack uses shared free infrastructure with no DPA, no
> private networking, no PITR backups, and public demo credentials. Load only
> the synthetic seed data. Never enter real patient information.

## Prerequisites

- This repository pushed to GitHub (public is fine; it is already public).
- A free [Render](https://render.com) account (sign in with GitHub).
- A free [Neon](https://neon.tech) account (sign in with GitHub).

No CLI or credit card is required.

## Step 1 — Create the Neon database

1. Sign in at <https://console.neon.tech>.
2. **New Project**:
   - Name: `hrp-demo`
   - Postgres version: `16`
   - Region: **Singapore** (closest to India; match the Render region)
3. On the project dashboard, copy the **Connection string** (pooled
   connection, host contains `-pooler`).
4. Append the SSL requirement if it is not already present:

   ```
   postgresql://USER:PASSWORD@ep-xxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

Neon's free plan scales to zero when idle; the first API request after a quiet
period may take a few seconds.

## Step 2 — Create the Render service from the blueprint

1. Open the one-click blueprint link:

   <https://render.com/deploy?repo=https://github.com/adityapandey2002/MATERNAL_HEALTH_HRP>

2. Authorize Render to read the repository if prompted.
3. Render reads `render.yaml` and shows the `hrp-demo` service plus the
   `DATABASE_URL` prompt.
4. Paste the Neon connection string from Step 1 into **DATABASE_URL**.
5. Click **Apply** / **Create Resources**.

Render builds `Dockerfile`, runs migrations, seeds the empty database, then
starts Fastify. First deploy typically takes 5–10 minutes.

`JWT_SECRET` and `JWT_REFRESH_SECRET` are generated by Render from the
blueprint, so they are never stored in git.

## How the seed stays safe

`docker-entrypoint.sh` runs `dist/db/demo-bootstrap.js` on every boot:

- `SEED_DEMO_DATA` is not `true` → it does nothing.
- the `users` table already has rows → it does nothing.
- the `users` table is empty and the opt-in is `true` → it loads the synthetic
  dataset once.

It never calls the destructive `db:seed` path against a populated database.
Set `SEED_DEMO_DATA=false` in Render after the first boot if you want the
bootstrap to be a no-op (optional).

## Free-tier behavior and limits

- The service spins down after ~15 minutes of inactivity. The next request
  cold-starts in roughly 30–60 seconds.
- 512 MB RAM, shared CPU. The server caps the database pool at 10 connections.
- Neon free plan: ~0.5 GB storage and scale-to-zero. The synthetic dataset is
  a few hundred kilobytes.
- Render free services do not support custom domains with managed TLS on the
  free plan; use the `onrender.com` URL.

## Operations

### Logs

Render dashboard → `hrp-demo` → **Logs**. Look for:

```
[entrypoint] applying database migrations
Applied migration 001_baseline ...
[bootstrap] empty database; loading synthetic demo data
Seed completed
[entrypoint] starting server on port 10000
```

### Re-seed a demo database

Only safe when the database is empty. In the Neon SQL editor:

```sql
truncate responsibilities, sync_queue, supervision_alerts, referrals, visits,
  patients, users, facilities restart identity cascade;
```

Then either restart the Render service or open a Render shell and run
`node packages/server/dist/db/demo-bootstrap.js` (the service's shell keeps
`SEED_DEMO_DATA` set).

Alternatively, set `RESET_DEMO_DATA=true` on the Render service, restart it,
and then unset the variable. The entrypoint truncates and reseeds on boot;
leaving the variable set would wipe data on every restart.

### Rollback

- **Bad app release:** Render dashboard → **Deploys** → previous deploy →
  **Rollback**. This redeploys the last healthy image without touching data.
- **Bad commit on `main`:** `git revert <sha> && git push`; `autoDeploy` ships
  the revert.
- **Migrations:** every migration is additive/forward-only. Reverting code does
  not downgrade the schema. If a migration itself is wrong, fix forward with a
  new migration.
- **Nuclear option:** suspend the Render service and delete the Neon project.

### Cost control

Free on both sides. To stop spending quota, suspend the Render service; to
delete all data, delete the Neon project.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Deploy fails with `Invalid configuration: JWT_SECRET ...` | Blueprint values not generated | Render → Environment → confirm both JWT values are 32+ chars and different |
| `Invalid configuration: DATABASE_URL is required` | Prompt left blank | Paste the Neon URL into `DATABASE_URL`, then redeploy |
| Crash loop with `getaddrinfo` / `ECONNREFUSED` | Wrong Neon host or missing `?sslmode=require` | Recopy the pooled connection string |
| `/ready` returns 503 `{"reason":"migrations"}` | Migrations did not finish | Check logs; the entrypoint retries five times |
| Login succeeds then immediately returns to login | Cookies blocked / wrong origin | Use the `onrender.com` URL directly, not an embedded preview |
| First request takes ~1 minute | Render and Neon cold start | Expected on free tier |
| Static routes 404 but `/health` works | Client build missing from image | Check that `packages/client/dist/index.html` was copied; `SERVE_CLIENT=true` is implied by `NODE_ENV=production` |

## Local smoke test of the same image

```powershell
$env:PATH = "C:\Users\ADITYA\AppData\Local\Programs\DockerDesktop\resources\bin;" + $env:PATH
docker compose up -d db
docker exec hrp-db-1 psql -U hrp -d postgres -c "drop database if exists hrp_deploy" -c "create database hrp_deploy"

docker build -f Dockerfile -t hrp-demo:local .

docker run --rm --name hrp-demo-local --network hrp_default -p 8080:8080 `
  -e PORT=8080 `
  -e DATABASE_URL="postgresql://hrp:hrp_dev@db:5432/hrp_deploy" `
  -e JWT_SECRET="local-demo-jwt-secret-at-least-32-chars" `
  -e JWT_REFRESH_SECRET="local-demo-refresh-secret-at-least-32-chars" `
  -e SEED_DEMO_DATA=true `
  hrp-demo:local
```

Then open <http://localhost:8080>. Drop `hrp_deploy` when finished.
